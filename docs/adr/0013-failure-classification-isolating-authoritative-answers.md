# ADR 0013 — Upstream fault isolation from authoritative negative answers

- **Status**: accepted
- **Date**: 2026-09-27
- **Phase**: 3 — Upstream pool and Do53 forwarder

## Context

In DNS resolution, a query result can fail at two completely different layers:

1. **Upstream infrastructure faults**: Network timeouts, connection drops, socket
   resets, transaction ID mismatches, malformed packet bytes, or `SERVFAIL`
   generated by an upstream resolver unable to complete downstream queries.
   These indicate that the upstream transport or server infrastructure is
   degraded or failing.
2. **Authoritative negative answers**: Legitimate DNS responses asserting domain
   status codes such as `NXDOMAIN` (domain does not exist, RFC 1035 §4.1.1),
   `NODATA` (domain exists but has no records of the requested type), or
   `REFUSED` (server policy refuses to answer for this name). These represent
   valid, successful DNS protocol exchanges delivering authoritative answers.

If an upstream pool or health monitor treats all non-success DNS outcomes as
upstream failures, standard client activity — such as browsing typos, querying
internal ad-tracking subdomains that do not exist, or querying zones rejected by
an upstream policy — would register as upstream faults.

This would falsely inflate latency estimates, increment consecutive failure
counters, trip circuit breakers, and erroneously evict healthy upstreams, opening
a trivial denial-of-service vector against the resolver.

## Decision

**Explicitly classify upstream outcomes using `FailureClass`, distinguishing
`UpstreamFault` from `AnswerFault`.**

- **Classification types**: `styx_resolution::domain::upstream::FailureClass`
  partitions errors into:
  - `FailureClass::UpstreamFault`: Network I/O errors, timeouts, connection
    refusals, upstream `REFUSED` responses (declining service), malformed wire
    encoding, ID mismatches, and synthetic canary probe failures.
  - `FailureClass::AnswerFault`: Valid protocol responses returning `NXDOMAIN`,
    `SERVFAIL` for client domain queries (e.g. DNSSEC validation failures on
    broken names), `FORMERR`, or `NOTIMP`.
- **Health penalty isolation**:
  - Only `UpstreamFault` increments consecutive failure counters, penalizes
    passive latency estimates, or advances the circuit breaker toward the `Open`
    state.
  - `AnswerFault` responses are treated as successful network exchanges delivering
    authoritative protocol answers. They do not trip circuit breakers or degrade
    health tracking.
- **Failover behavior**:
  - `UpstreamFault` triggers failover to subsequent upstreams according to the
    configured selection strategy.
  - `AnswerFault` returns the authoritative negative answer directly to the
    caller without failing over to alternative upstreams, adhering to DNS
    correctness.

## Consequences

- Circuit breaker state and health metrics reflect genuine transport and server
  availability rather than end-user querying behavior.
- High volumes of `NXDOMAIN` queries (from scanner probes, spam lookups, or local
  client typos) cannot cascade into upstream pool outages.
- Resolvers correctly respect negative authoritative answers without issuing
  redundant duplicate queries across secondary upstreams.
