# The DNSSEC differential corpus (Phase 06, task 6d.7): every name with its expected
# outcome written down, so the run against a local unbound (6d.8) has something to be
# wrong against. "Behaves as expected" is not a criterion until each line says what that is.
#
# One entry per line:
#
#   name TYPE  RCODE AD VERDICT  HARD_FAIL_RCODE
#
# RCODE, AD and VERDICT are styx's reply and logged verdict under WarnOnly, for a client
# that sets DO (AD is "ad" when set, "-" when clear). HARD_FAIL_RCODE is the RCODE once 6d.9
# has flipped the failure mode; every other field is the same after the flip, except that a
# SERVFAIL carries no AD. Under WarnOnly a Bogus answer is served with AD clear, so the bogus
# family's verdict is read from the log ("DNSSEC validation completed", verdict=Bogus).
#
# Observed on 2026-11-27 with delv (BIND 9.20.31) and through 1.1.1.1. Where styx's
# algorithm policy differs from those validators the line says so; such a disagreement
# with unbound is expected and is a policy, not a bug. Any other disagreement must be
# triaged to a named cause before 6d.9 flips the mode: "DNS moved" is a cause only once
# the movement itself has been confirmed.
